# 事绩通小程序 · 企业微信接入开发需求

> 项目：事绩通（shijitong-miniprogram）
> 技术栈：Taro + 微信云开发
> 日期：2026-03-31
> 目标：接入企业微信，实现组织架构同步、自动日报/周报生成、消息推送

---

## 一、数据层改造 — 建立「上下级关系」

### 1.1 需求背景

当前 `users` 表只有 `role`（executor/creator/admin/manager），没有上下级映射关系，无法实现"自动汇报给直属上级"的核心功能。

### 1.2 改造内容

给 `users` 集合新增以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `manager_id` | String | 直属上级的 openid |
| `department_id` | String | 所属部门 ID（关联 departments 集合） |
| `report_to` | Array\<String\> | 汇报对象 openid 列表（支持多级汇报） |
| `wecom_userid` | String | 对应的企业微信成员 UserID（用于打通企业微信） |

### 1.3 数据来源方案

**推荐方案 A：从企业微信通讯录 API 自动同步**

- 调用企业微信 API `GET /cgi-bin/user/list` 获取部门成员列表
- 调用 `GET /cgi-bin/user/get` 获取单个成员详情（含 `direct_leader` 直属上级字段）
- 调用 `GET /cgi-bin/department/list` 获取部门树
- 定期同步（建议每天一次，或手动触发）

**备选方案 B：小程序内手动设置**
- 在用户个人设置页增加"我的上级"选择功能
- 从已有用户列表中选择
- 简单但需要人工维护

### 1.4 依赖信息（需提供）

- 企业微信 **CorpID**（企业 ID）
- 企业微信自建应用 **AgentID + Secret**（需在管理后台创建应用，权限开通通讯录读取）

## 二、新增云函数

### 2.1 `wecom-sync` — 企业微信组织架构同步

**功能：**
- 从企业微信 API 拉取部门列表 → 写入 `departments` 集合
- 从企业微信 API 拉取成员列表 → 更新 `users` 集合的上下级关系
- 支持全量同步和增量同步

**接口设计：**

```
触发方式：定时触发器（每天凌晨 2:00）或手动调用
入参：{ mode: "full" | "incremental" }
出参：{ success: true, data: { synced_users: 45, synced_depts: 8, updated_relations: 12 } }
```

**核心逻辑：**
1. 调用企业微信 `getAccessToken` 获取 access_token
2. 递归获取部门树 → 更新/创建 `departments` 记录
3. 遍历部门获取成员 → 匹配已有用户（通过 `wecom_userid`）
4. 更新 `manager_id`、`department_id`、`report_to`
5. 记录同步日志到 `sync_logs` 集合

**企业微信 API 列表：**
- `GET /cgi-bin/token` — 获取 access_token
- `GET /cgi-bin/department/list` — 获取部门列表
- `GET /cgi-bin/user/list?department_id={id}` — 获取部门成员
- `GET /cgi-bin/user/get?userid={id}` — 获取成员详情（含直属上级）

### 2.2 `daily-report` — 自动日报生成与推送

**功能：**
- 每日定时汇总每个用户的任务数据
- 生成简洁有重点的日报
- 推送给本人 + 直属上级

**接口设计：**

```
触发方式：定时触发器（每天 18:00）
入参：{ user_openid?: String, date?: "YYYY-MM-DD" }
出参：{ success: true, data: { sent_count: 23 } }
```

**日报格式：**

```
📋 张三 · 3月31日日报

✅ 已完成（2项）
  · 客户回访方案 → 评分 90
  · Q2预算表 → 评分 85

⏳ 进行中（3项）
  · 品牌合作方案 ⚠️ 明天截止
  · 活动策划案 周五截止
  · 数据分析报告 下周一截止

📊 本周概况
  完成 8/12 | 均分 82 | 及时率 75%
```

**核心逻辑：**
1. 查询当天有更新的所有任务（`updated_at` 在今日范围内，且用户是执行人或发布人）
2. 按用户分组
3. 根据用户的 `report_to` 确定推送对象（本人 + 直属上级）
4. 生成日报文本
5. 调用 `wecom-notify` 推送

**查询条件：**
- 已完成：`status === 'completed' && complete_date === today`
- 进行中：`status === 'pending' || status === 'in_progress'`，按截止日期排序，标注临期任务
- 逾期：`status !== 'completed' && require_date < today`

### 2.3 `wecom-notify` — 企业微信消息推送

**功能：**
- 替换现有飞书 Webhook 通知（`feishu-notify`）
- 通过企业微信应用消息 API 推送

**接口设计：**

```
入参：{
  to_users: [openid1, openid2],    // 接收人 openid 列表
  msg_type: "text" | "markdown",   // 消息类型
  title: String,                   // 消息标题
  content: String,                 // 消息内容
  task_id?: String                 // 关联任务 ID（可选，用于跳转）
}
出参：{ success: true, data: { sent_count: 2 } }
```

**核心逻辑：**
1. 根据 openid 查找对应的 `wecom_userid`
2. 调用企业微信 `POST /cgi-bin/message/send` 发送应用消息
3. 支持文本消息和 Markdown 消息
4. 记录推送日志

**企业微信 API：**
- `POST /cgi-bin/message/send` — 发送应用消息

## 三、周报功能升级

### 3.1 现状

已有 `weekly-report` 云函数，仅查询已完成的任务，基于 `score` 和 `attribution_tags` 统计。

### 3.2 需要升级的点

| 改造项 | 说明 |
|--------|------|
| 增加推送能力 | 当前只是查询，不推送。需接入 `wecom-notify` 自动发送 |
| 增加上级抄送 | 周报除了发给本人，也要发给直属上级 |
| 增加未完成项 | 当前只统计已完成的，需补充"未完成 + 逾期"的列表 |
| 支持团队周报 | 管理者可查看下属所有成员的周报汇总 |

### 3.3 升级后的周报格式

```
📋 张三 · 第14周周报（3.24-3.30）

✅ 本周完成（8项）  均分 82
  · 客户回访方案 90分
  · Q2预算表 85分
  · ...

❌ 逾期未完成（2项）
  · 品牌合作方案（逾期2天）
  · 供应商合同（逾期1天）

⏳ 进行中（3项）
  · 活动策划案 → 周五截止
  · 数据分析报告 → 下周一截止

📊 数据
  完成率 8/12(67%) | 及时率 75% | 归因TOP：沟通协调(3)
```
