## 📊 数据库设计

### tasks 表 - 新增字段

```javascript
{
  // ... 原有字段 ...
  
  // 子任务相关（新增）
  parent_task_id: String,      // 父任务 ID（子任务才有，主任务为空）
  is_subtask: Boolean,         // 是否为子任务（默认 false）
  
  // 子任务独有字段
  collaborators: Array,        // 协助人列表 [{openid, name, role}]
  flow_history: Array,         // 流转记录 [{from, to, date, note}]
  current_executor: String,    // 当前执行人（流转时变更）
  
  // 进度控制
  subtask_count: Number,       // 子任务总数（主任务用）
  completed_subtask_count: Number,  // 已完成子任务数（主任务用）
}
```

## 🎯 核心规则

### 1. 层级关系
- 主任务可以拆分为多个子任务
- 子任务不能再拆分子任务（只支持两级）
- 子任务通过 `parent_task_id` 关联主任务

### 2. 独立属性
| 属性 | 规则 |
|------|------|
| 执行人 | 子任务独立设置，可与主任务不同 |
| 截止日期 | ≤ 主任务截止日期 |
| 优先级 | 子任务不设置优先级，继承主任务 |
| 协助人 | 子任务独有，支持多人协作 |
| 任务流转 | 仅在子任务分支支持 |

### 3. 进度联动
- 子任务全部完成后，弹窗询问主任务执行人是否完成主任务
- 主任务完成时，自动检查子任务状态
- 主任务取消/删除时，级联处理子任务

### 4. 评分逻辑
- 只对主任务评分
- 子任务完成度影响主任务评分参考

## 🔄 任务流转流程

```
子任务创建 → 分配执行人 → 执行中 → 申请流转 → 审批 → 变更执行人 → 完成

流转记录：
{
  from_executor: String,    // 原执行人
  to_executor: String,      // 新执行人
  flow_date: Date,          // 流转日期
  reason: String,           // 流转原因
  approved_by: String,      // 审批人
  note: String              // 备注
}
```

## 🔧 云函数设计

### subtask-create
```javascript
输入：
- parent_task_id: 主任务 ID
- task_name: 子任务名称
- task_description: 描述
- executor_id: 执行人
- require_date: 截止日期
- collaborators: 协助人列表

验证：
- 主任务存在
- 截止日期 ≤ 主任务截止日期
- 执行人有效

输出：
- 子任务创建成功
- 更新主任务 subtask_count
```

### subtask-list
```javascript
输入：
- parent_task_id: 主任务 ID

输出：
- 子任务列表
- 进度统计（已完成/总数）
```

### subtask-update
```javascript
输入：
- subtask_id: 子任务 ID
- status: 状态
- flow_request: 流转申请（可选）

流转逻辑：
- 检查流转权限
- 记录流转历史
- 更新 current_executor
```

### task-check-completion
```javascript
输入：
- parent_task_id: 主任务 ID

逻辑：
- 查询所有子任务状态
- 如果全部完成，返回提示
- 更新主任务进度字段
```
